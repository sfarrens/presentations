## Continuous integration and deployment I
### GitHub Actions

--

> At this stage our code is looking pretty good! We have documentation and tests all set up, but we do have to build the documentation and run the tests manually. 😩

> This means we might get lazy and forget to run our tests before merging or indeed to update our documentation afterwards. 😨

> This is where the concept of *continuous integration* (CI, i.e. constantly running tests) and *continuous deployment* (CD, i.e. constantly deploying things like API documentation) comes into play.

--

> Following the [Git workflow](#/5) we established previously, let's start by creating a feature branch for this work.

```bash
git checkout -b chore/add-ci-cd
```

--

> Both GitHub and GitLab provide tools to automatically run tests and deploy static HTML pages.

> Let's start with GitHub, which offers CI/CD services via [GitHub Actions](https://github.com/features/actions).

> To begin we will need to create a *YAML* file for CI and put it in `.github/workflows`. This file can have any name, but let's call it `ci.yml` for now.

```bash
mkdir .github/workflows
touch .github/workflows/ci.yml
```

--

> Inside this file we will add the following.[$^{36}$](#/15/37)

```yml
name: CI

on:
  pull_request:
    branches:
     - main

concurrency:
  group: ${{ "{{" }} github.workflow }}-${{ "{{" }} github.ref }}
  cancel-in-progress: true
```

--

> Let's start with a job for linting.[$^{37}$](#/15/38) [$^{38}$](#/15/39)

```yml
jobs:
  lint:
    name: Lint
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Install uv
        uses: astral-sh/setup-uv@v5
        with:
          python-version: "3.12"
          enable-cache: true

      - name: Install dependencies
        run: uv sync --group lint

      - name: Lint
        run: |
          uv run ruff format --check .
          uv run ruff check .
          uv run mypy src
```

--

> Next, a separate job to actually run our tests.

```yml
  test-full:
    name: Run CI Tests
    runs-on: ${{ "{{" }} matrix.os }}

    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest]
        python-version: ["3.12"]

```

> This runs a job called *Run CI Tests* on both Ubuntu and macOS machines using Python 3.12 — our tests need to pass on every platform we support.[$^{39}$](#/15/40)

--

> Now we can add some steps to our job.

```yml
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Install uv
        uses: astral-sh/setup-uv@v5
        with:
          python-version: ${{ "{{" }} matrix.python-version }}
          enable-cache: true

      - name: Check Python version
        run: uv run python --version
```

> This will checkout our repository, and install `uv` itself along with the exact Python version we asked for — the same deterministic pinning we get locally.

--

> Next we will install the packages we need for running our tests — just the `test` group this time, since linting already happened in its own job.

```yml
      - name: Install dependencies
        run: uv sync --group test
```

> Finally, we run the tests.

```yml
      - name: Run tests
        run: uv run pytest
```

--

> Let's add, commit and push all of the changes to the feature branch.[$^{40}$](#/15/41)

```bash
git add -A
git commit -m "Add CI workflow"
git push origin chore/add-ci-cd
```

> Then open a Pull/Merge request as explained in the [previous section](#/5). Opening the PR is itself the test — since our workflow triggers `on: pull_request`, GitHub will run it immediately using the workflow file from this branch.

> Did your `lint` and `test-full` jobs both run?

--

> Now, let's add a CD workflow to the same branch. As [before](#/10/3), we will add a new YAML file, this time called `cd.yml`.

```bash
touch .github/workflows/cd.yml
```

--

> At the top of the file we will add the following.

```yml
name: CD

on:
  push:
    branches:
     - main
```

> This specifies that the workflow is called `CD` and that it should only run if we push changes to the `main` branch.[$^{41}$](#/15/42)

--

> As we are just deploying our API docs, we only need one machine for our job.[$^{42}$](#/15/43)

```yml
jobs:
  docs:
    name: Deploy API Documentation
    runs-on: ubuntu-latest
```

--

> The first two steps of this job are exactly the same as the `test-full` [CI job](#/10/7) (`enable-cache` included), just installing the `docs` group instead.

```yml
      - name: Install dependencies
        run: uv sync --group docs
```

--

> Next, we need to build our docs, exactly as we did locally [before](#/9/10).

```yml
      - name: Build API documentation
        run: |
          uv run sphinx-apidoc -Mfeo docs/source src/mycosmo
          uv run sphinx-build docs/source docs/build
```

--

> Last but not least, we need to deploy our API documentation so the whole world can see it.[$^{43}$](#/15/44) 🥹

```yml
      - name: Deploy API documentation
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ "{{" }} secrets.GITHUB_TOKEN }}
          publish_dir: docs/build
```

--

> To get this CD workflow to work we will need to set up a few things on GitHub. Let's create a special branch called `gh-pages`.[$^{44}$](#/15/45)

```bash
git checkout --orphan gh-pages
git reset --hard
git commit --allow-empty -m "Initializing gh-pages branch"
git push origin gh-pages
git checkout chore/add-ci-cd
```

--

> Then on GitHub go to

<mermaid>
graph LR;
    a["Settings"]
    b["General"]
    c["Workflow permissions"]
    a --> b --> c
</mermaid>
<!-- .element: style="height: 100px;" -->

> and select *Read and write permissions*.

--

> Finally, it's worth enabling a *branch protection rule* requiring both the `lint` and `test-full` checks to pass before a PR can be merged into `main`.[$^{45}$](#/15/46) Without this, someone could merge a PR with failing tests, and `CD` would happily deploy the resulting (possibly broken) documentation straight to production.

--

> Let's add, commit and push these changes to the same branch.[$^{46}$](#/15/47)

```bash
git add -A
git commit -m "Add CD workflow"
git push origin chore/add-ci-cd
```

> Then merge your Pull/Merge request. Did your CD job run? Can you see your API documentation at `<user name>.github.io/mycosmo`?
