## Using AI

--

> AI coding assistants have become a standard part of the developer toolkit — worth understanding, even if you choose not to use them yourself.

--

> A few of the current major players:

- [GitHub Copilot](https://github.com/features/copilot) — in-editor completions and chat, tightly integrated with GitHub
- [Claude Code](https://www.claude.com/product/claude-code) — an agentic coding assistant that runs in your terminal
- [Cursor](https://cursor.com/) — an AI-native code editor
- [Codex](https://openai.com/codex/) — OpenAI's coding agent
- [Gemini Code Assist](https://codeassist.google/) — Google's assistant, integrated with VS Code and Google Cloud

> New tools appear constantly — the specific names matter less than understanding the category.

--

> These tools fall roughly into two categories:

|                   | What it does                                                        |
| ----------------- | ----------------------------------------------------------------------- |
| In-editor / chat  | Suggests completions, answers questions — you stay in the driving seat  |
| Agentic           | Plans and executes changes across files with some autonomy — you review the diff |
<!-- .element: style="font-size: 70%;" -->

> The line between the two keeps blurring — most tools now offer both modes.

--

> One term you'll hear a lot is *vibe coding*, coined by AI researcher Andrej Karpathy in early 2025.[$^{72}$](#/17/73)

> "I just see stuff, say stuff, run stuff, and copy paste stuff, and it mostly works."

> The idea: describe what you want in natural language, and accept the AI's output with minimal review — "forget that the code even exists."

--

> Vibe coding is genuinely useful for prototyping, throwaway scripts, and exploring an unfamiliar library. It is *not* a substitute for understanding code you intend to keep, maintain, or ship.

> Karpathy himself has since described the term as already somewhat dated, as tools shift toward more deliberate "agentic engineering" — you still direct and review, even as the AI does more of the typing.

--

> A few precautions worth taking, whichever tool you use:

--

> **Review everything.** You're still the author of record — `git blame` will point at you, not the model. If you can't explain what a piece of code does, don't commit it.

--

> **Verify dependencies before installing them.** LLMs sometimes *hallucinate* package names that sound plausible but don't exist — attackers have started pre-registering these names, a technique known as *slopsquatting*.[$^{73}$](#/17/74)

> `uv.lock` and the other reproducibility tooling from earlier in this course are exactly the kind of defence this needs — pin what you actually resolved and reviewed, not whatever an assistant suggested.

--

> **Mind what you paste.** Cloud-hosted AI tools may retain or train on what you send them. Check your institution's or employer's policy before pasting proprietary code, unpublished results, or sensitive data into a chat window.

--

> **Watch for licensing issues.** Generated code can closely resemble snippets from its training data, with licensing terms that may not be compatible with your project.

--

> **Nothing skips the pipeline.** AI-generated code still needs to pass the same tests, linting, type checking and review as anything else in this course — arguably more so, since it wasn't written with your codebase's specific context in mind.

--

> There's no single agreed community standard yet, but a few patterns are emerging:

- Some projects reject AI-generated contributions outright, others require disclosure — practices vary a lot from one project to the next.[$^{74}$](#/17/75)
- [`AGENTS.md`](https://agents.md/) has emerged as a shared convention for giving coding agents repository-specific context — read natively by dozens of tools.[$^{75}$](#/17/76)

> When in doubt: check the project's contribution guidelines, and when contributing to someone else's project, disclose AI use rather than assume it's fine.

--

> The tools will keep changing — the underlying practices from this course (tests, linting, type checking, documentation, review) are what make any code, AI-assisted or not, trustworthy.
